# AI 像素擂台：炸弹人 II

请提交一个仅使用 Python 标准库的 `bot.py`，实现 `decide(state) -> str`。每回合所有活人同时出招：`up`、`down`、`left`、`right`、`bomb`、`stay`。非法、缺失、异常或超时动作按 `stay`。这是一份完整的规则和公开状态合同。

## 地图、道具和赛制

坐标 `(x,y)` 左上为 `(0,0)`，x 向右，y 向下。上、下、左、右分别是 `(0,-1)`、`(0,1)`、`(-1,0)`、`(1,0)`。一回合只能移动一格，放弹不能同时移动。`.` 空地、`#` 砖墙（木箱）、`@` 钢墙；地形不包括玩家、炸弹或道具。不能越界或走进墙。

正式单挑 2 人、13×13，出生点 `(1,1)`、`(11,11)`；正式乱斗 4 人、13×13，按 id 顺时针出生在 `(1,1)`、`(11,1)`、`(11,11)`、`(1,11)`。默认上限 270 回合，第 80 回合开始压墙。引擎也接受其他奇数尺寸和人数，例如 10 人 25×25，其他人数沿圆环选出生点；实际参数总以 state 为准。

外边界和偶数 x、偶数 y 的交点为钢墙。可放砖的格按种子、以四向旋转轨道 65% 概率放砖。四个角的 3×3 内侧出生区域清除砖墙，保留钢墙。单挑也清除全部四角，避免地图偏向。每个砖墙轨道独立以 40% 概率藏道具，有道具时按火力:加弹:踢弹 = 4:4:2 抽取，同一个轨道的位置和种类完全相同。40% 是生成概率，单张小地图的实际比例会浮动。隐藏道具不出现在状态或画面中，直到砖被炸开。

开局每人火力半径 2、同时最多 1 颗弹、没有踢弹能力。踩到已露出的道具立即拾取并移除：`fire` 半径 +1，最高 8；`bomb` 同时可放弹数 +1，最高 6；`kick` 永久获得踢弹能力。到达上限或已有能力仍消耗道具并计一次拾取。火力升级不改变已经放出的炸弹。道具不挡玩家和爆炸射线，但挡滑行炸弹。

## 每回合严格结算顺序

所有人看到上回合结束的公开状态，同时提交动作。下面每个阶段完成后才进入下一阶段。

1. **玩家移动和踢弹意图。**方向动作的目标若有本回合开始时的炸弹，有踢弹能力者提出对该弹的踢动意图，自己留在原地；没有能力者被挡。对同一颗弹恰好一个意图时，将其滑动方向设为该方向，可以改变旧方向；两个或更多意图全部取消，并停止这颗弹原有的滑动。意图是否生效与玩家 id 无关。目标没有炸弹时，必须为空地，而且没有回合开始时的活人才能提出普通移动。多人竞争同一空格全部不动；不能互换或跟进刚离开的玩家格。踢弹不算竞争普通目标格，被挡不致死。
2. **拾取。**在玩家移动后的格子有露出道具就拾取，原地不动也会拾取。抢同一格的普通移动已经在阶段 1 取消，不会有两人捡同一个道具。拾取先于本回合爆炸，因此可能捡完又被炸死。刚拾取的踢弹能力从下回合起可用于提出踢动意图；脚下拾取的火力或加弹则立即适用于本回合的放弹阶段。
3. **放弹。**动作是 `bomb`、自己场上的弹数未达个人上限、脚下没有炸弹时，在脚下生成一颗全局递增 id 的炸弹，记录当前火力半径。新弹 fuse=3，当回合不减。可以站在自己刚放的弹上并在下一回合离开；离开后，弹消失前不能走回来。死者的弹继续倒计时、可以击杀。
4. **滑行。**此前滑动的弹与本回合踢动的弹都尝试沿方向移动一格。用此阶段开始时的同一份炸弹位置判断：越界、钢墙、砖墙、另一颗弹（即使它也要移动）、移动后的活人、尚未拾取的道具都会挡停。两颗或更多弹要滑到同一个空格时全部停在原格。不能互换、不能跟进其他弹刚离开的格。挡停后方向清空，障碍消失也不会自动继续，必须再次被踢。玩家刚走进滑行目标格则挡停炸弹；玩家刚离开该格则允许滑入。玩家仍不能走进炸弹回合开始的格。新放的弹也会挡其他弹。弹不会推人或捡道具。
5. **倒计时、连锁和射线。**回合开始就存在的弹 fuse 减 1，到 0 爆炸；滑行的弹在滑动后的位置爆炸。刚放的弹不减，但也可以被连锁引爆。每颗弹炸自身格，再向四个方向各伸出其 radius 格。钢墙阻断且不受影响；砖被炸毁且阻断该条射线；遇到另一颗弹则连锁引爆，并在该弹格停止此条射线。玩家、道具不挡射线。所有连锁都使用本阶段开始时的同一张地形和炸弹位置快照，本回合炸碎的砖不会让同回合别的射线穿透。初始到期弹按 id 从小到大入队，连锁按上、下、左、右发现顺序入队，每颗只爆炸一次。
6. **道具、砖墙和爆炸出局。**本阶段开始前已经露出的道具被任意射线扫到就消失。然后统一移除炸碎的砖、露出其隐藏道具；新露出的道具保留，不被本回合其他射线烧毁。砖的摧毁归属取扫到它的最小炸弹 id 的主人。处在任何火焰格的玩家同时出局，死因 `blast`。多颗弹命中时，击杀归属取最小炸弹 id 的主人；归属自己时 killer=null、不记击杀。死亡弹主也能得分。只在这一回合末判一次火焰，下一回合不会残留伤害。爆炸中的弹都移除。
7. **压墙。**从 `crush_start`（默认 80）开始每回合落一块钢墙。基础路径从 `(0,0)` 向右走完整条最外侧顶边，再向下、向左、向上，顺时针螺旋向中心推进。整条路径按 `crush_rotation` 顺时针旋转 0、90、180 或 270 度，使落墙起始角随种子均衡变化；开局地图（含出生区清理）生成完毕后，按此顺序只保留当时不是 `@` 的格：空地和砖墙都保留，外圈钢墙和内部钢柱全部跳过。路径开局即固定，不会因之后炸砖而重新排序或改变落墙回合；每格只落一次。标准 13×13 共 96 格，第一块在 `crush_start` 当回合落下，此后每回合一块，期间不空转。默认旋转量为 seed 模 4，实际值写入记录 config。落墙改地形为 `@`，该格剩余炸弹直接消失、不爆炸，露出或隐藏道具也移除。该格活人直接出局，死因 `crush`，killer=null、不计击杀。若同回合已被炸死，保留 `blast` 死因；到期弹先爆炸，再落墙。下一回合火焰清空。全图落完后不再落墙。状态预告接下来 5 块（含各自回合）；不足 5 块时返回余下的数量。

第 7 回合放弹：回合末 fuse=3，第 8 回合末 2，第 9 回合末 1，第 10 回合玩家移动、炸弹滑行后爆炸。玩家有第 8、9、10 回合三次移动机会，但可能更早被连锁。

**结束与名次：**活人只剩 1 人或 0 人，或达到 `max_turns` 就结束，不再延长计算剩余炸弹。活人排在死人前；死人按出局回合从晚到早；同回合出局者或都存活到上限者按击杀数降序；仍相同则并列，采用竞赛名次（例如 1、1、3、4）。不按座位、拾取或炸砖数破平局。

## 进程与 CPU 限制

Python 3.13，仅标准库，提交一个文件。每局新加载，模块全局变量可在局内保存，局间清零。裁判按种子初始化 `random`。加载限 1 秒 CPU，第 1 回合限 1 秒 CPU，以后**每步 50 毫秒 CPU**，另有每次回复 3 秒墙钟兜底。异常、超时、非法返回按 `stay`，连续三次失败或进程未响应会结束该进程，本局后续均 `stay`；一次成功回复清零连续失败次数。沙箱禁止读写文件、联网、开子进程，print 不参与协议。不要依赖其他选手内存或裁判实现。

## state 逐项说明

每次输入均为普通、可 JSON 序列化的 dict/list/int/bool/string/null。修改它不会影响引擎。玩家、炸弹请按 id 查找，不要把列表下标当作 id。

| 字段 | 含义 |
| --- | --- |
| `turn` | 即将结算的回合，首回合为 1 |
| `max_turns` | 整局回合上限 |
| `width`, `height` | 棋盘宽高，当前为正方形 |
| `num_players` | 开局人数 |
| `you` | 你的座位 id，0..num_players−1 |
| `grid` | height 个字符串，每行 width 个字符，只有 `.`、`#`、`@` |
| `players` | 全部活人，包含你；每项字段见下表，死者不在该列表 |
| `bombs` | 全部场上炸弹，含死者此前放的弹；每项字段见下表 |
| `items` | 全部已露出的道具，每项 `{x, y, kind}`，kind 为 `fire`、`bomb` 或 `kick`；无隐藏内容 |
| `bomb_fuse` | 新弹的完整引信，默认 3 |
| `max_radius` | 火力升级上限，默认 8 |
| `max_bombs` | 弹数升级上限，默认 6 |
| `crush_start` | 第一块墙落下的回合，默认 80 |
| `crush_rotation` | 基础螺旋的顺时针旋转次数（0、1、2、3），公开且整局固定 |
| `next_crush` | 接下来最多 5 块墙，按时间排序，每项 `{x, y, turn}`，turn 为准确落墙回合 |
| `crushed` | 已经落墙的格，按落下顺序排列，每项 `[x,y]`；不包含开局就是钢墙的格 |

`players` 的每一项：

| 字段 | 含义 |
| --- | --- |
| `id`, `x`, `y` | 座位编号和当前坐标 |
| `alive` | 在 state 中恒为 true；frame 中包含死者 |
| `death_turn`, `death_cause`, `killer` | 活人为 0、空字符串、null；frame 中死者为准确回合、`blast`/`crush`、击杀者或 null |
| `kills` | 累计击杀其他玩家数，不含自杀和压墙 |
| `bombs`, `bricks`, `pickups` | 累计成功放弹、炸砖、拾取次数，均非排名破同分依据 |
| `radius` | 该玩家新放炸弹的十字半径，不含中心 |
| `bomb_limit` | 该玩家同时在场炸弹数上限 |
| `can_kick` | 是否拥有踢弹能力 |
| `active_bombs` | 该玩家当前在场炸弹数 |
| `can_bomb` | active_bombs < bomb_limit；脚下有弹仍不能放 |

`bombs` 的每一项：

| 字段 | 含义 |
| --- | --- |
| `id` | 全局递增、整局不重复的炸弹编号 |
| `owner` | 原始放弹者 id，踢动或连锁不改变归属 |
| `x`, `y` | 上回合结束的当前坐标 |
| `fuse` | 上回合结束的剩余引信，1 代表本回合移动、滑动后爆炸（除非更早被连锁） |
| `radius` | 放置时固定的火力半径 |
| `sliding` | 是否正滑行，等价于 direction 非 null |
| `direction` | `up`、`down`、`left`、`right` 或 null |

例如旋转量为 0 时，`next_crush=[{"x":1,"y":1,"turn":80}, ...]` 在第 1 回合即已可见；到第 80 回合仍预告第一格，结算后该格进入 crushed，预告从第 81 回合的格开始。

## 回放与画面合同

`frame()` 是独立的完整快照：包含上述所有字段（去掉 `you`），`turn` 改为已经结算的回合（初始为 0），`players` 包含所有座位和死亡信息，增加 `flames`（本回合火焰格 `[x,y]` 数组）。不会暴露隐藏道具。`export` 导出 `frames[0..turns]`、累计 events、完整 death 三元组、place、seats 和实际 config。events 的每项有 t、type；类型包括 `bomb`、`explode`、`brick`、`reveal`、`pickup`、`kick`、`die`、`crush`，以及已露出道具被烧毁的 `item_destroy`。踢动冲突事件带 ids、direction=null、cancelled=true；滑行位置以每帧炸弹状态为准。压墙事件带 at、被移除的 bombs id 数组、被移除的 item 种类或 null。
